Introduction

The AIDD workshop ended at forge:promote — your plan is ready and your app is built. This guide covers the next three skills that test your implementation: backend tests, UI feature files, and Playwright specs running against your live app.

Note: Each skill checks its own prerequisites automatically. Just run them in order.

forge:build-tests
Step 1 — Backend tests

Reads the BDD test suites from forge:spec-tests and writes executable test code that runs against your app.

Prompt

Claude Code 
forge:build-tests

Build the e2e tests for dishly-wave-1. Read the e2e test suite and
generate executable test code that runs against the running app.

Output

  • Executable test files for e2e, contract, and integration suites
  • Pass/fail report confirming all scenarios run correctly
forge:spec-ui-e2e
Step 2 — Gherkin feature files

Converts ui-e2e-test-suite.md into Gherkin .feature files — one per UI surface — ready for Playwright.

Prompt

Claude Code 
forge:spec-ui-e2e

Generate feature files for dishly-wave-1. Convert the ui-e2e-test-suite
into Gherkin .feature files, one per UI surface.

Output

  • Gherkin .feature files in features/us/<surface-name>/
  • Each scenario tagged with @SC-N for traceability to requirements
forge:build-playwright-tests
Step 3 — UI specs + run

Takes the .feature files, navigates your live app via browser to discover real selectors, generates Playwright .spec.ts files, runs them, and auto-fixes any failures.

Prompt

Claude Code 
forge:build-playwright-tests

Build Playwright tests for dishly. The feature files are ready — generate
the spec files, run them against the local app, and fix any failures.

Output

  • Playwright .spec.ts files in tests/bdd/us/<feature-area>/
  • Real CSS selectors discovered from the live DOM
  • Auto-fix loop — up to 3 cycles to resolve failing selectors
  • Validation report confirming all specs are correct
